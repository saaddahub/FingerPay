# FingerPay — Threat Model & Verification Matrix (v3)

This document maps every threat in `docs/SPEC.md` §3 to our concrete controls in the TypeScript modular monolith and PostgreSQL database triggers, along with the automated test that verifies each control.

| ID | Threat | Controls Implemented | Automated Verification |
|---|---|---|---|
| **T1** | Forged debit through the API | No public settle route. `POST /api/v1/pos/charges/:id/thumb` requires an active paired ECDSA P-256 terminal signature + 60s window + single-use nonce. `fp_app` has no `UPDATE` grant on `fp.accounts(balance)`; balances move only via `fp.trg_journal_entry_apply_balance`. | `auth-and-terminals.test.ts`, `ledger-payments-and-views.test.ts` |
| **T2** | Replay of a captured request | Canonical string `FPv1\nMETHOD\npath?query\nterminal\ntimestamp\nnonce\nbodySha256` signed with ECDSA P-256; `(terminal_id, nonce)` stored in `fp.request_nonces` PK; timestamps > 60s rejected. | `auth-and-terminals.test.ts` (replay -> 409, stale -> 401, tampered body -> 401) |
| **T3** | Database dump leaks thumbs / CNICs | Raw fingerprint images are never captured or stored. PII (`full_name_enc`, `cnic_enc`, `phone_enc`, `account_no_enc`, `totp_secret_enc`) is encrypted with AES-256-GCM bound to `fp:v1:<table>:<column>:<rowId>` AAD. DB `CHECK` constraints reject non-encrypted blobs. | `crypto.test.ts`, `20261118000300_ledger_and_payments.sql` |
| **T4** | Leaked public / anon key | Application schema `fp` has `REVOKE ALL ON SCHEMA fp FROM PUBLIC`. Only authenticated staff JWTs (EdDSA or Supabase JWKS) and paired terminal keys can invoke routes. | `ready.test.ts` |
| **T5** | Merchant charges a shopper who isn't there | Per-tap limits (`PKR 5,000` salary / `PKR 2,000` student), daily caps (`PKR 15,000` / `PKR 5,000`), SMS receipt on every payment and decline, `Reply DISPUTE`, and maker-checker refunds. | `ledger-payments-and-views.test.ts` |
| **T6** | Cashier refunds or voids to themselves | Reversals negate the original journal entries, paying back **only** the original payer. Same-day void is restricted to `MERCHANT_OWNER`. Dispute refunds require `maker_id <> checker_id` enforced in both TypeScript and DB `CHECK` constraint. | `ledger-payments-and-views.test.ts` (cashier void -> 403, self-approve refund -> 403) |
| **T7** | Double charge (double tap, retry, race) | Charge session is locked `FOR UPDATE`; retrying a `PAID` charge replays the original receipt (`replayed: true`) without debiting twice. Second charge for the same shopper + store + amount within 15s is declined with `DECLINED_DUPLICATE_TAP`. | `ledger-payments-and-views.test.ts` |
| **T8** | Overdraft by racing concurrent payments | Accounts are locked in deterministic ascending `id` order (`FOR UPDATE`); `CHECK (balance >= 0)` on `fp.accounts` rejects any negative balance inside the transaction. | `ledger-payments-and-views.test.ts` (concurrent payments overdraft test) |
| **T9** | Insider edits the ledger or audit log | `BEFORE UPDATE OR DELETE` and `BEFORE TRUNCATE` triggers block mutations on `journals`, `journal_entries`, `payment_attempts`, `raast_transfers`, and `audit_events` even for `fp_owner`. `audit_events` is SHA-256 hash-chained; `/api/v1/bank/integrity` detects any tampered row. | `ledger-payments-and-views.test.ts` (superuser tamper with row 3 detected) |
| **T10** | Guessing thumbs at a terminal | 3 failed thumb attempts lock the charge session (`CHARGE_LOCKED`); 10 unknown thumbs in 10 minutes pause the terminal (`DECLINED_TERMINAL_THROTTLED`). | `payments/service.ts` |
| **T11** | Cloned / silicone fingerprint (AePS-style) | Shopper replies `LOCK` to any FingerPay SMS to freeze thumb payments immediately; locked attempts decline with `DECLINED_THUMB_LOCKED` and send a security alert SMS; only a branch officer (AAL2) can unlock. | `ledger-payments-and-views.test.ts` |
| **T12** | Wrong person matched at scale (1:N) | `BiometricMatcher` supports both 1:N and 1:1 (`require_claim` policy flag checking last 4 digits of CNIC or phone). | `biometrics/matcher.ts` |
| **T13** | Stolen terminal phone | Non-extractable WebCrypto / Android Keystore ECDSA P-256 private key; owner or bank admin can revoke the terminal immediately (`POST /api/v1/terminals/:id/revoke`). | `auth-and-terminals.test.ts` |
| **T14** | Stolen staff password | Argon2id password hashing, 5-attempt lockout (`423 LOCKED`), mandatory TOTP MFA (`AAL2`) for all bank roles, 15-minute EdDSA JWTs, and rotating refresh tokens with family reuse revocation. | `auth-and-terminals.test.ts` |
| **T15** | XSS, CSRF, clickjacking | Strict CSP with per-request nonces, `frame-ancestors 'none'`, `SameSite=Strict` refresh cookie, and `Origin` allowlist check on all state-changing requests. | `http-hardening.test.ts` |
| **T16** | One store reads another store's data (IDOR) | Merchant scope is derived exclusively from the authenticated staff JWT and paired terminal record, never from client parameters. | `ledger-payments-and-views.test.ts` |
| **T17** | Privacy leak to the merchant | Declined rows never expose the shopper's name (`shopper: null`); settled rows show first name + initial only (`"Ayesha K."`); shopper balance is never returned to any merchant screen. | `ledger-payments-and-views.test.ts` |
| **T18** | Secrets or PII in logs | Pino redaction list strips `cnic`, `phone`, `token`, `thumb`, `account`, `password`, `totpSecret`, `authorization`, `cookie`, and `x-fp-signature` at all nesting levels. | `config-and-log.test.ts` |
| **T19** | CSV formula injection in ledger export | Every CSV cell is quoted; cells starting with `= + - @ TAB CR` are prefixed with `'`. | `pricing-and-csv.test.ts`, `ledger-payments-and-views.test.ts` |
| **T20** | Supply-chain attack | Locked `pnpm-lock.yaml`, `pnpm audit --prod` and `gitleaks` in `.github/workflows/ci.yml`. | `.github/workflows/ci.yml` |
| **T21** | Abuse / denial of service | Per-terminal and per-staff rate limits, 16 KB body limit (`413 PAYLOAD_TOO_LARGE`), and `statement_timeout=5s` / `lock_timeout=3s` on `fp_app`. | `http-hardening.test.ts`, `ready.test.ts` |
| **T22** | Demo shortcuts left on in production | `loadConfig` refuses startup when `FP_ENV=production` and `FP_DEMO_MODE=true`; `/api/v1/demo/*` returns `404` when `FP_DEMO_MODE=false`. | `config-and-log.test.ts`, `ledger-payments-and-views.test.ts` |
